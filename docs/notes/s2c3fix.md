## What cocotb actually does (read from the pinned sources)
- `_gpi_triggers._EdgeBase`: one trigger per (signal, edge kind) (`signal.rising_edge`,
  `.falling_edge`, `.value_change` are cached). `Trigger._register` primes (registers a
  VPI value-change callback) when the first waiter arrives; the GPI callback is one-shot,
  so a fired trigger is re-primed by its next waiter.
- `verilated_vpi.cpp` `callValueCbs`: walks the `cbValueChange` list in registration order,
  stops at the element that was last when the walk began (callbacks added during the walk
  are skipped), and each `VerilatedVpiCbHolder` compares against its own `m_varo` copy of
  the value, made when the callback was registered. `settle_value_callbacks` repeats the
  walk until nothing fires; with inertial writes values cannot change inside a settle, so
  a second walk fires nothing.
- `GPITrigger._react` runs `_do_callbacks` (waiters in registration order) and then the
  whole event loop (`_event_loop.run`, FIFO) inside each callback.
- `First`/`Combine`/`with_timeout` (`_concurrent_waiters._wait`): one helper `Task` per
  operand, started with `_start_next` (front of the queue); the caller awaits an
  `_InternalEvent`. `FIRST_COMPLETED` cancels the other helpers; a `PENDING` helper is
  cancelled by `_schedule_resume` (back of the queue), and the event is set when the last
  helper finishes. `ClockCycles._wait` awaits one `RisingEdge` trigger `n` times, inline.
- `Timer.__init__` raises `ValueError` for `time <= 0`.

All of the reviewer's claims were confirmed by real runs before any simjig change (the new
goldens), and the 14 existing goldens regenerated byte for byte.

## D1: value changes fire one group at a time
- `waits.rs`: edge waiters live in `Group`s keyed by (slot, `EdgeKind`), each with the
  `seq` of the registration that primed it and its own snapshot (Verilator's per-callback
  copy). `groups` is a `Vec` sorted by `primed` (push keeps it sorted; `seq` only grows);
  `group_of[slot][kind]` finds a live group. A group is unprimed when it fires or loses its
  last waiter. `fire_next_change(model, until, after, out)` resumes the walk after `after`,
  skips groups primed after `until` (the walk start), updates snapshots of changed groups
  and fires the first whose edge happened.
- `sched.rs` `fire_value_changes`: walk, `wake_sorted`, `run_ready`, repeat. Called from
  `apply_and_compare`, so after every eval+apply and every ReadWrite apply.
- Why per-group snapshots, not the old per-slot one: a `rising(x)` group primed from a
  `changed(x)` wake at x's rising edge must snapshot x = 1 and wait for the next edge
  (`edge_kinds` 35 ns, `phases::changed_and_rising_on_one_signal_are_separate_groups`);
  a shared snapshot not yet updated for x would fire it at once.
- Why not simpler (rule 5): firing all changed groups together and sorting waiters
  differently cannot produce the `Event.wait()` task between two groups' waiters, which
  every new golden shows; the kernel has to run tasks between groups. Cost: one
  `run_ready` per fired group (each wakes a task anyway) and one `partition_point` per step.
- Executor-semantics change: wake order inside one comparison is now priming order, not
  global waiter registration order. Every existing golden replay and swarm test passes
  unchanged; trace hashes may differ where the two orders differ (none is pinned).

## D2: combinator hops
- `combinator::hop(losers)`: counts `WaitTable::cancelled` (registrations removed before
  they fired) around dropping the losers, then `yield_now` once, twice if a pending wait was
  cancelled. `first!` passes its operand array, `join!` passes `()`, `with_timeout` drops
  its loser and timer (held in `Option`s, the future pinned as `pin!(Some(..))`) and calls
  `hops` directly.
- Why yields, not helper tasks: a yield puts the caller at the back of the ready queue,
  exactly where cocotb's internal event (or the cancelled loser, then the event) lands, and
  costs no spawn, allocation or task name. The 25/35/45/55/65 ns rounds of
  `combinator_hop` pin both hop counts (one yield too few or too many fails a round).
- Residual difference (README): operand *bodies* run in the caller, not in their own
  helper task; only code between two awaits inside one operand can see a different order.
  No golden exercises it.

## Timer(0)
Kept at await (documented on `Timer::new` and in the README). Moving the check into the
`const fn` would make a `Timer` built before `Sim::run` panic outside the run, and a const
panic cannot name the call site in its message, both of which
`phases::trigger_misuse_points_at_the_line_that_made_the_trigger` requires; dropping
`const` would break `const` items (an API change for no correctness gain).
